There are other factors to consider, such as performance, security, maintainability, and how easily the application can grow over time. This has changed the way I approach problems. Instead of immediately jumping into writing code, I try to understand the problem, think through possible solutions, and consider the advantages and disadvantages of each approach.

Software Design and Engineering

Artifact Description

The artifact I've selected for my software engineering and design enhancement is a Contact Management application. This project was originally created in CS-320, Software Testing, Automation, and Quality Assurance. The application allows contact information to be created, updated, and deleted. Each contact contains an ID, first name, last name, address, and phone number. The application was developed in Java and tested with JUnit.

Enhancements and Skills Demonstrated

Selecting this artifact allowed me to demonstrate my skills in Java, object-oriented programming, validation, and testing. While reviewing my original code, I noticed areas that could be improved, especially when handling invalid information. I created reusable validation methods and improved how the application handles input. The application now checks for blank values, and phone numbers must contain exactly 10 numeric digits.

Making these enhancements also required me to update my JUnit tests. Before the enhancements, I had 31 passing tests. After expanding the test coverage, I now have 38 passing tests with no failures. This helped confirm that the changes were working as expected.

Course Outcomes

These enhancements demonstrate my progress toward the course outcomes by improving validation, implementing solutions, checking for duplicate contacts, and testing application functionality. They also helped me demonstrate how software engineering practices can improve the reliability and maintainability of an application.

Reflection

Making changes to this artifact taught me that the order of validation matters and that repeated code should be avoided when possible. I was concerned about breaking existing functionality while introducing reusable validation methods, but running my JUnit tests helped confirm that the application continued working.

Algorithms and Data Structures

Artifact Description

For this enhancement, I revisited my Contact Management application from CS-320, Software Testing, Automation, and Quality Assurance. The application was developed in Java and allows contacts to be created, updated, searched, and deleted. Originally, I stored contacts using an ArrayList.

Enhancements and Skills Demonstrated

Reviewing this application allowed me to identify weaknesses in my original approach and demonstrate my understanding of algorithms and data structures. I replaced the ArrayList with a HashMap, using the Contact ID as the key and the Contact object as the value.

With an ArrayList, the application would loop through the contacts to find a matching ID. Using a HashMap improves lookup operations from O(n) to O(1) on average. I was also able to use methods such as get(), put(), remove(), and containsKey() to manage contact information more efficiently.

Course Outcomes

This enhancement demonstrates my progress toward the course outcome of designing and evaluating computing solutions using algorithmic principles. I considered the advantages and disadvantages of different data structures before deciding which approach worked best for the application.

Reflection

This enhancement encouraged me to look deeper into the differences between ArrayLists and HashMaps. I learned how choosing a different data structure can affect the efficiency and overall behavior of an application. After making the changes, I ran the tests to confirm that the existing functionality continued working correctly.

Database Design

Artifact Description

The artifact I selected for my database enhancement is the Contact Management application originally created in CS-320, Software Testing, Automation, and Quality Assurance. The application allows contacts to be added, updated, deleted, and searched. Originally, contact information was stored in memory, meaning the data would be lost when the application stopped running.

Enhancements and Skills Demonstrated

Choosing this artifact gave me the opportunity to demonstrate my ability to improve an existing application by integrating a database. I decided to use PostgreSQL with Spring Boot and Spring Data JPA. I converted the Contact class into a JPA entity using @Entity and created a repository to manage database operations.

I also updated the service logic to communicate with the database repository rather than storing contacts in memory. This allowed me to demonstrate my skills working with PostgreSQL, relational databases, Spring Data JPA, and CRUD operations.

Course Outcomes

My approach was slightly different from my original plan. Instead of using a regular Java database connection, I chose Spring Data JPA with PostgreSQL. This provided a more structured approach to connecting the application to a database.

JPA also reduces the amount of repetitive SQL and connection code needed for common database operations. By keeping the database logic separate from the service logic, I made the application easier to maintain and expand.

Reflection

This enhancement gave me a better understanding of how the different application layers work together. One challenge I faced was ensuring that the existing functionality continued working while updating the application to use a database repository.

I also encountered issues when setting up Spring Boot and PostgreSQL. Overall, this enhancement improved my understanding of connecting an existing Java application to a relational database and managing persistent data.
